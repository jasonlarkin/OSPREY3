## SIMD reproducibility 

This repo contains multiple SIMD implementations and multiple analysis scripts. The goal is to make it possible to reproduce:
- **Correctness** (scalar vs SIMD outputs match within tolerance)
- **Performance** (scalar vs AVX2 vs AVX-512)
- **Hardware counters** (perf stat / cache hierarchy)
- **Roofline + cache plots**

### 1) One command to re-run everything

From repo root:

```bash
bash scripts/tools/run_all_simd_analysis.sh 5
```

To keep multiple experiments side-by-side (different SIMD variants, different compiler flags, etc), set an experiment label.
All plots will be written to `plots/<label>/` (filenames unchanged):

```bash
bash scripts/tools/run_all_simd_analysis.sh 5 my_experiment_label
```

Alternative:

```bash
export OSPREY_EXPERIMENT_LABEL=my_experiment_label
bash scripts/tools/run_all_simd_analysis.sh 5
```

This regenerates:
- `benchmark_results.csv`
- `arithmetic_intensity_measurements.csv`
- `plots/*.png`
- `tmp/*` (cache hierarchy CSVs, perf raw outputs)

### 2) SIMD implementations (what exists and how to select it)

#### ConfEcalc energy (Amber/EEF1 pairs)

Implemented in:
- `src/main/cc/ConfEcalc/energy_ambereef1.h` (runtime dispatch)
- `src/main/cc/ConfEcalc/energy_ambereef1_simd.h` (implementations)

Available implementations:
- **scalar**: baseline scalar version
- **avx2**: AVX2 vectorized version (exact exp path)
- **avx512**: AVX-512 vectorized version (exact exp path, when compiled)
- **avx2_fast_exp / avx512_fast_exp**: experimental fast-exp versions (if enabled in dispatch)

Selection:
- Bench binaries that force a specific implementation:
  - `benchmark_scalar_only`
  - `benchmark_avx2_only`
  - `benchmark_avx512_only`
- Runtime dispatch controls (used by some benchmarks/tests):
  - `OSPREY_FORCE_SCALAR=1` forces scalar path
  - `OSPREY_USE_FAST_EXP=1` selects the fast-exp implementation (if present for that ISA)

#### Rotation + Real3 kernels

Implemented in:
- `src/main/cc/ConfEcalc/rotation_simd.h`
- `src/main/cc/ConfEcalc/real3_simd.h`

Benchmark:
- `src/main/cc/ConfEcalc/tests/benchmark_rotation_operations.cpp`

It supports isolated runs (needed for perf stat):
```bash
./src/main/cc/ConfEcalc/build/benchmark_rotation_operations 2000 2000 --op rotation --impl scalar
./src/main/cc/ConfEcalc/build/benchmark_rotation_operations 2000 2000 --op rotation --impl simd
./src/main/cc/ConfEcalc/build/benchmark_rotation_operations 2000 2000 --op normalize --impl scalar
./src/main/cc/ConfEcalc/build/benchmark_rotation_operations 2000 2000 --op normalize --impl simd
```

#### TranslationRotation (TransRot) apply()

SIMD integration point:
- `src/main/cc/ConfEcalc/motions/transrot.h` dispatches to `apply_transrot_avx2_impl<T>()` when `USE_SIMD` and `T=double`.

#### Minimization (CCD) thread-level parallelism (OpenMP)

CCD minimization is implemented in:
- `src/main/cc/ConfEcalc/minimization.h` (`minimize_ccd`)

**Determinism vs. performance**:
- Default behavior is **serial/deterministic** (recommended for regression tests).
- If compiled with OpenMP (`USE_OPENMP`), an OpenMP path is available but is **opt-in** via:
  - `OSPREY_MINIMIZE_CCD_OMP=1`

Why opt-in?
- Parallel execution can change floating-point operation ordering and cause tiny numeric drift.
- This has historically shown up as occasional failures in strict f64 tests (e.g. `minimizeEnergies_native_1DG9_6f_f64` at epsilon `1e-4`).

To experiment with it:
```bash
export OSPREY_MINIMIZE_CCD_OMP=1
./gradlew test --tests "edu.duke.cs.osprey.energy.compiled.TestNativeConfEnergyCalculator.minimizeEnergies_native_1DG9_6f_f64"
```

### 3) Analysis scripts (what to run)

#### Energy benchmarks
- `scripts/tools/benchmark_comprehensive.sh [num_runs]` → `benchmark_results.csv`
- `scripts/tools/plot_benchmark_results.py [benchmark_results.csv]` → plots into `plots/`

#### Empirical arithmetic intensity (perf-based)
- `scripts/tools/measure_arithmetic_intensity.sh <system_size>` appends to `arithmetic_intensity_measurements.csv`
- `scripts/tools/plot_roofline.py` → `plots/roofline_plot.png`
- `scripts/tools/plot_roofline_combined.py` → `plots/roofline_plot_combined.png`

#### Cache hierarchy
- Pair computation cache hierarchy (scalar/avx2/avx512 only):
  - `scripts/tools/analyze_cache_hierarchy.sh <system_size>` → `tmp/cache_hierarchy_<system_size>.csv`
  - `scripts/tools/plot_cache_hierarchy.py <system_size>` → `plots/cache_hierarchy_<system_size>.png`
- Rotation/normalize cache hierarchy:
  - `scripts/tools/profile_rotation_cache_hierarchy.sh` → `tmp/rotation_cache_hierarchy.csv`
  - `scripts/tools/plot_rotation_cache_hierarchy.py` → `plots/rotation_cache_hierarchy_{rotation,normalize}.png`
  - `scripts/tools/summarize_rotation_cache_hierarchy.py` prints scalar vs SIMD speedups/counters from that CSV

### 4) Perf limitations

On some systems (often WSL), **perf may be unavailable or unsupported for the running kernel**.

What happens in that case:
- `arithmetic_intensity_measurements.csv` rows are written with **`-1` sentinel values** and `bytes_source=perf-unavailable`
- Cache-hierarchy scripts may emit CSVs with **`-1`** for unsupported counters or write header-only files
- Plot scripts will **skip invalid points** or **fall back to timing-based estimates** (roofline)

Typical WSL fix:
- Install the matching linux-tools package for the WSL kernel (the perf error text usually prints the exact package name)
- Example package names look like:
  - `linux-tools-<kernel>-microsoft-standard-WSL2`
  - `linux-tools-standard-WSL2`

Even with perf installed, **LLC events may be unsupported** (`<not supported>`). In those cases, scripts record missing counters as `-1` and plots omit LLC-specific panels.
