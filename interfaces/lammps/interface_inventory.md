# LAMMPS: interface inventory 

## Object graph (core)

- **`Pair`**
  - encapsulates a pair style (nonbonded / pairwise or many-body potential interface).
  - owns per-type cutoffs, flags for optional capabilities (`single_enable`, `manybody_flag`, etc.).
- **`Fix`**
  - a generic hook object called at lifecycle/timestep phases (integration, constraints, thermostats, coupling, bookkeeping).
  - may contribute energy/virial and/or change state.
- **`Modify`**
  - holds the active lists of `Fix` and `Compute` objects.
  - orchestrates when each fix hook runs (`pre_force`, `post_force`, `end_of_step`, etc.).

## Structural pattern (high value)

- **Registry-by-style-name**:
  - “what to run” is selected by style name strings; concrete types live in many `*_*.cpp` files.
- **Hook scheduling**:
  - the engine advances time and invokes well-defined hook points; extensibility is implemented by overriding hook methods.

## Extensibility seams to map explicitly

- adding a new **pair style**
- adding a new **fix style**
- adding a new **compute style**
